# Архитектура

## Общая схема

```
Telegram  <--->  bot.py ----> storage.py (SQLite: настройки чатов, задачи)
                   |                 ^
                   v                 |
              jobs.py (очередь, один воркер) ---> pipeline.py
                                                     |
        +--------------+--------------+--------------+----------------+
        v              v              v              v                v
 highlights/      slicer.py    ffmpeg_utils.py   subtitles/      audio_mix.py
 (динамика)       (нарезка)    (резка + 9:16)    (Whisper+Pillow) (музыка)
```

`main.py` запускает в одном asyncio-цикле (как в Vinted_Telegramm_Bot) две части:

1. Telegram-бот (long polling): принимает видео, показывает панель, хранит настройки.
2. Воркер очереди: берёт задачи по одной и выполняет `run_pipeline` в потоке (`asyncio.to_thread`),
   чтобы бот отвечал на команды во время рендера.

## Конвейер (`pipeline.py`)

1. **План и резка.**
   - *Хайлайт:* `highlights/finder.py` извлекает 4 сигнала (разность кадров, оптический поток Farneback,
     RMS, спектральный поток), нормирует, сглаживает фильтром Савицкого-Голея, применяет выбранный детектор,
     затем медианный фильтр, буфер +5 с, слияние близких отрезков и подгонку под целевую длину.
     Отрезки вырезаются и сразу переводятся в 1080x1920 одним проходом ffmpeg, затем склеиваются без перекодирования.
   - *Нарезка:* `slicer.compute_cut_points` выбирает случайные длины в диапазоне, остаток короче минимума
     присоединяется к предыдущему клипу.
2. **Субтитры.** Звук клипа извлекается в WAV, Whisper даёт слова с таймкодами, `renderer.py` рисует по 3 слова,
   активное слово подсвечено. Если речи нет или нет звуковой дорожки, этап пропускается с пометкой.
3. **Музыка.** Случайные треки из `data/music` склеиваются под длину клипа, гасятся до заданной громкости,
   в конце плавное затухание, микшируются с оригинальным звуком. Видеопоток копируется без перекодирования.
4. Результат перемещается в `data/output/<имя видео>/`, временная папка удаляется.

Все клипы после резки имеют одинаковые параметры кодирования (H.264, 30 fps, AAC 44.1 кГц),
поэтому `concat` без перекодирования безопасен.

## Формат 9:16 (`ffmpeg_utils.vertical_filter`)

| Режим | Результат |
|-------|-----------|
| `blur` | Кадр целиком по центру на размытом увеличенном фоне (по умолчанию) |
| `crop` | Кадр заполняет 1080x1920, края обрезаются |
| `off` | Без изменений |

## Очередь задач (`jobs.py`)

- Статусы: `queued`, `running`, `done`, `failed`, `cancelled`, `interrupted`.
- Отмена: флаг проверяется между этапами конвейера. Задача в очереди отменяется сразу.
- Прогресс отправляется правкой одного сообщения не чаще раза в 4 секунды (лимиты Telegram).
- Файлы, которые бот скачал сам (`data/work/uploads`), удаляются после задачи. Файлы из `inbox` и `output` не трогаются.
- После перезапуска задачи в состояниях `queued`/`running` помечаются `interrupted`: наполовину готовый рендер возобновить нельзя.
- Если шорт больше лимита отправки, бот присылает путь к файлу.

## Бот (`bot.py`)

- Доступ: декоратор `restricted` пускает только `ALLOWED_USER_IDS`; пустой список значит «никому».
- Панель настроек — inline-клавиатура. Callback-данные: `opt:<токен>:<поле>`, `go:<токен>`, `drop:<токен>`,
  `in:<номер>`, `cancel:<задача>`. Токен одноразовый и хранится в `user_data`, повторное нажатие безопасно.
- Задача и настройки принадлежат чату, создавшему их: отмена и просмотр чужих задач невозможны.
- `concurrent_updates(True)`: долгая загрузка по ссылке не блокирует кнопки.
- Меню команд регистрируется при каждом старте (`set_my_commands`).

## База данных (`storage.py`)

SQLite, две таблицы:

- `chat_settings(chat_id, options)` — JSON с `PipelineOptions`.
- `jobs(id, chat_id, source, options, status, error, outputs, created_at, finished_at)`.

## Настройки (`config.py`)

`AppConfig` читается из `.env` (токен, папки, Whisper, доступ). `PipelineOptions` — параметры одной задачи
(режим, длины, алгоритм, формат, субтитры, стиль, музыка), хранится в JSON на чат и проверяется `validate()`.
